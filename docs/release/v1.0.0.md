# treesitter-lang v1.0.0 — API Freeze

**The 0.2.0 surface, frozen.** v1.0.0 makes the tree-sitter grammar generator
a stable contract: three types, the validation and output guarantees that
make them worth depending on, and the rules `sexp` renders by. The code is
unchanged from 0.2.0. What changed is the promise, recorded in
`docs/API.md#stability`: no breaking change before `2.0`.

## What is treesitter-lang?

Tree-sitter grammars built in Rust. A language made with the `-lang` family
already has a hand-written parser producing lossless `syntax-lang` trees;
editors want a tree-sitter grammar for the same language. treesitter-lang
writes that grammar from Rust — generated from the same tables the parser
uses, validated against tree-sitter's own rules before tree-sitter runs, and
emitted as `grammar.js` or `grammar.json` — and renders the parser's trees as
tree-sitter corpus tests, so `tree-sitter test` holds the two parsers to each
other. It is one of the FEAT-tier crates of the `-lang` language-construction
family.

## What's new in 1.0.0

### The stability promise

Within `1.x`:

- **The surface is frozen.** `Rule` and its seventeen constructors;
  `Grammar` with its eight builder methods, four emitters, and two
  renderers; `Error` and its fifteen variants and their fields; and the
  `syntax_lang` re-export. Additions — new constructors, builder methods,
  error variants — are minor releases. `Error` is `#[non_exhaustive]`, so
  match it with a wildcard arm.
- **The validation contract holds.** A grammar that validates is one
  `tree-sitter generate` loads, up to what only its parse tables reveal
  (conflicts, and extras whose end it cannot tell). A grammar validation
  refuses is one tree-sitter refuses, crashes on, or hangs on — apart from
  the documented stricter checks (an empty `choice`, an `inline` entry naming
  nothing, empty patterns and empty strings inside tokens). Checks may be
  refined in a minor release only to follow tree-sitter more closely.
- **The output contract holds.** `to_js` describes exactly the grammar
  built; `to_json` writes tree-sitter's `grammar.json` for it; both generate
  the same parser, and the JSON matches, byte for byte, the file the
  supported tree-sitter versions write.
- **The `sexp` rendering rules are fixed** — which names are shown, spliced,
  or left out, and the indentation.
- **`syntax-lang` 1 is a public dependency**, and **MSRV 1.85** a
  compatibility surface: raising it is a documented minor change.

Not promised: the exact layout of `grammar.js` (it may get prettier; what it
describes may not change), which problem validation reports first when a
grammar has several, `Display` and `Debug` text, and performance figures.

### How the contract was earned

The validation contract is the one that needed evidence, and it got three
kinds before the freeze:

- **Probing.** Every check was written after probing the tree-sitter 0.27 CLI
  with small grammars built to isolate it — about 300 in all, covering
  reachability, token merging, hidden literals, supertype shapes, inline
  limits, and the grammars that crash or hang tree-sitter.
- **Adversarial review.** An independent review attacked the crate's claims
  with hand-built grammars and found fourteen problems, from repetitions of
  nothing to unescaped control characters in patterns. All were fixed in
  0.2.0.
- **Differential fuzzing.** A fuzzer generated random grammars — every rule
  type, externals sharing rule names, word, inline, and supertype settings —
  and ran each through validation and through `tree-sitter generate`. Each
  disagreement was traced to its cause in tree-sitter and fixed, round after
  round, until runs of thousands of fresh grammars on the final code found
  none beyond the documented differences.

The output contract is checked on every change by the CI `tree-sitter` job,
and was checked by hand against five older tree-sitter releases:

| tree-sitter | `grammar.json` loads | Same parser from both formats | `grammar.json` byte-identical |
|---|:---:|:---:|:---:|
| 0.25 – 0.27 | yes | yes | yes |
| 0.24 | yes | yes | all but the final, empty `reserved` field |
| 0.20, 0.22 | yes | not checked | — |

## Breaking changes

**None.** 1.0.0 is 0.2.0 with the promise made: the surface, behaviour, and
output are identical.

## Verification

Run on Windows x86_64 and Linux (WSL2 Ubuntu, from a sibling-free copy, as CI
checks the crate out), Rust stable and the 1.85 MSRV; macOS runs in the CI
matrix:

```bash
cargo fmt --all -- --check
cargo clippy --all-targets -- -D warnings
cargo clippy --all-targets --all-features -- -D warnings
cargo clippy --all-targets --no-default-features -- -D warnings
cargo test
cargo test --all-features
cargo test --no-default-features
cargo build --examples
RUSTDOCFLAGS="-D warnings" cargo doc --no-deps --all-features
cargo +1.85 test --all-features
cargo +1.85 clippy --all-targets --all-features -- -D warnings
cargo +1.85 fmt --all -- --check
cargo deny check
cargo audit
cargo publish --dry-run
bash dev/conformance.sh target/conformance   # tree-sitter 0.27.0
```

All green. Counts at this tag (identical for every feature combination):

- 46 unit + 69 integration + 2 conformance + 5 property + 114 doctests.

Benchmark baselines (x86_64, release profile, into a reused buffer; `emit`
includes validation):

| Benchmark | Windows | Linux (WSL2) |
|---|---:|---:|
| `emit/js/small` (9 rules) | ~2.6 µs | ~1.5 µs |
| `emit/json/small` | ~3.8 µs | ~2.6 µs |
| `emit/js/large` (1,000 rules) | ~0.74 ms | ~0.61 ms |
| `emit/json/large` | ~1.1 ms | ~0.93 ms |
| `emit/escapes` | ~44 µs | ~33 µs |
| `sexp/10000` | ~170 µs | ~157 µs |
| `sexp/100000` | ~1.7 ms | ~1.6 ms |
| `build/large` | ~0.72 ms | ~0.51 ms |

## What's next

Additive `1.x` work, none of it a commitment: named precedences
(tree-sitter's `precedences` field), reserved-word sets, pattern flags,
anonymous aliases, and a `Grammar::check` that validates without emitting.

## Installation

```toml
[dependencies]
treesitter-lang = "1"
```

MSRV: Rust 1.85.
